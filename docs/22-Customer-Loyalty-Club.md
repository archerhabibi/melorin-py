# باشگاه مشتریان: امتیاز، سطح و پاداش (هر فروشگاه باشگاه خودش را دارد)

> شاخه: `feat/customer-loyalty-club` · migration: `0040_customer_loyalty_club` · قواعد خالص: `melorin/domain/loyalty.py` · سرویس: `melorin/modules/loyalty/service.py`

## قاعده‌ی اصلی
مثل رفرال و کوپن (docs/21)، امتیاز از فروشگاهی به فروشگاه دیگر نمی‌رود. هر فروشگاه برنامه، سطح‌ها و پاداش‌های خودش را دارد؛ هزینه‌ی پاداش از **حساب هزینه‌ی همان فروشگاه** (`acc_loyalty_expense`) پرداخت می‌شود و فقط به مشتریان **خودش** می‌رسد. منطق فقط در Core است؛ سایت، ربات و پنل‌ها فقط نمایش می‌دهند و فراخوانی می‌کنند. چیزی که از قبل داریم دوباره ساخته نمی‌شود: سفارش تکمیل‌شده و بازگشت وجه از outbox همان رویدادهای رفرال می‌آیند و پاداش با همان دفتر کیف پول واریز می‌شود.

## قواعد
* **کسب امتیاز**: به‌ازای هر `earn_unit` از مبلغ خالص پرداخت‌شده (بعد از تخفیف) `points_per_unit` امتیاز، ضربدر ضریب سطح فعلی، با سقف اختیاری `max_points_per_order`.
* **سطح**: فقط از «مجموع امتیاز کسب‌شده در طول عمر» تعیین می‌شود، نه خرج‌کردن. نردبان از ۰ شروع می‌شود، آستانه‌ها صعودی‌اند، حداکثر ۱۰ سطح، ضریب حداکثر ۵ برابر. پیش‌فرض: برنزی، نقره‌ای، طلایی، الماسی.
* **پاداش‌ها**: فعلاً یک نوع، `wallet_credit` (اعتبار کیف پول همان فروشگاه و همان ارز). موجودی (`stock`) و سقف برای هر مشتری اختیاری است.
* **بونوس‌ها**: بونوس اولین سفارش برای خود مشتری، و بونوس معرف وقتی دوستِ دعوت‌شده‌اش اولین سفارش را تکمیل می‌کند.
* **بازگشت وجه**: امتیاز همان سفارش برمی‌گردد. اگر مشتری قبلاً خرج کرده باشد، مازاد «بدهی امتیاز» می‌شود و از کسب‌های بعدی کم می‌شود؛ موجودی هرگز منفی نمی‌شود.
* **تنظیم دستی**: افزودن یا کم‌کردن امتیاز با دلیل اجباری و ثبت در audit.
* **تکرار امن**: همه‌ی ثبت‌ها و برداشت‌ها با کلید idempotency یکتا هستند؛ ارسال دوباره چیزی را دوبار ثبت نمی‌کند.

## مدل داده
`loyalty_programs`, `loyalty_tiers`, `loyalty_accounts`, `loyalty_transactions` (دفتر امتیاز), `loyalty_rewards`, `loyalty_redemptions`، همگی با `store_id`.

## API
| مسیر | چه کسی | کار |
|---|---|---|
| `GET /stores/{id}/loyalty` | مشتری همان فروشگاه | موجودی، سطح، سطح بعدی، پاداش‌ها، آخرین ردیف‌ها |
| `GET /stores/{id}/loyalty/history` | مشتری | تاریخچه‌ی صفحه‌بندی‌شده |
| `GET /stores/{id}/loyalty/redemptions` | مشتری | برداشت‌های خودش |
| `POST /stores/{id}/loyalty/rewards/{rid}/redeem` | مشتری | خرج امتیاز (هدر `Idempotency-Key`) |
| `GET/PUT /stores/{id}/loyalty/manage/program` | صاحب نمایندگی / ادمین | برنامه |
| `PUT /stores/{id}/loyalty/manage/tiers` | همان | کل نردبان یکجا |
| `GET/POST/PUT /stores/{id}/loyalty/manage/rewards` | همان | پاداش‌ها |
| `GET /stores/{id}/loyalty/manage/summary` | همان | آمار باشگاه |
| `POST /stores/{id}/loyalty/manage/adjust` | همان | تنظیم دستی امتیاز |

شناسه‌ی فروشگاه همیشه از URL می‌آید، نه بدنه. نماینده فقط باشگاه فروشگاه خودش را مدیریت می‌کند؛ ادمین هر فروشگاه، فروشگاه اصلی هم.

## رابط کاربری
* **store-web (مشتری)**: کارت «باشگاه مشتریان» در داشبورد: امتیاز، سطح و پیشرفت تا سطح بعد، پاداش‌ها با دکمه‌ی دریافت، تاریخچه.
* **store-web (نماینده)**: تب «باشگاه مشتریان»: برنامه، سطح‌ها، پاداش‌ها، آمار.
* **admin-web**: صفحه‌ی «باشگاه مشتریان فروشگاه‌ها» برای مدیریت باشگاه هر فروشگاه.
* **ربات تلگرام**: دکمه‌ی «باشگاه من» برای دیدن امتیاز و سطح و دریافت پاداش.
